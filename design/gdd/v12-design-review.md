## 2. 与 TALENTS 的边界（必须守住）

| 维度 | TALENTS（天赋） | 海克斯（V12） |
|---|---|---|
| 触发 | 每次升级（一局约 30 次） | 每 3 关一次（一局 33 次） |
| 选择权 | 3 选 1，无稀有度 | 3 选 1，4 档稀有度 + 双保底 |
| 作用 | 基础属性线性成长，纯被动 | 构筑方向 + 新行为（13 条机制型），可叠 5 层 |
| 能否重复 | 可，同类反复出现 | 可，但同条需间隔 3 次事件 |
| 设计意图 | 保底变强，升级不白给 | 决定这一局「玩哪个流派」 |

## 3. 实现要点（给程基岩）

- `game.wave` 应重命名为 `level`：现有 `spawnEnemy` 内 `const stage=game.wave` 与新公式 `stage=(n-1)%20+1` **同名不同义**，是最高危的错源。
- 状态机新增 `cleared` / `channel`；替换现有 `waveState==='rest'` + `game.rest=3`，`update()` 的 296 / 303 行是唯一改动点。
- 海克斯不写 `p.atk`：新增 `p.hex={atkMult,hpMult,...}`，在 `damageEnemy` / `hurtPlayer` 两处结算，`stat()` 保持不动。
- UI 复用 `#talentPanel` / `.talent-card` 结构新建 `#hexPanel`，支持 1/2/3 键选择与 Esc 延后。
- `spawnWave()` 改为「先算总数 + 入队 + 每 0.85s 放一批」，**禁止**在 `update()` 里按帧补刷。
## 4. 三个已知风险与缓解

- **节奏碎片化**：33 次暂停打断战斗。缓解：3 卡横排 + 键盘 1/2/3，允许「稍后选」（最多保留 1 个待选，通道生成前强制结算）。
- **机制递归爆炸**：尸爆 → 击杀 → 再尸爆。缓解：单帧机制触发 ≤3 次、机制 ICD ≥0.15s、尸爆与反伤弹不吃海克斯乘区只吃基础攻击。
- **固定数量与首领召唤冲突**：现有 boss 的 `summonCd` 会召唤，违反「一次性固定数量」。缓解：召唤物标记为不计入总数，上限 6，不参与清空判定。
